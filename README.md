# 昇嶺排程中樞

先算再答應，料比線先到。業務、生管、倉庫、產線、課長、儀表板六個角色共用一套資料，五個智能體協助整理與說明。

## 功能

| 角色 | 能做什麼 |
|---|---|
| 業務 | 貼上客戶訊息 → AI 整理成變更單（缺欄位會追問）→ 送生管；排好後拿到回覆草稿 |
| 生管 | 試算 2–4 個方案（完成時間、新增延誤、增加換線、等料、罰款風險）→ 確認派發 |
| 倉庫 | 依黃燈（剩 200 片）備料、藍燈（剩 50 片）推料、送達線邊亮綠牌 |
| 產線 | 看板：正在做、剩幾片、下一張、黃藍綠燈；作業員不用輸入 |
| 課長 | 核准破例；錄音或打字，AI 整理成日報 |
| 儀表板 | 異常、指標、四條線狀態、每一個動作的紀錄 |

- **數字由排程演算法算**，AI 只負責整理文字和寫說明；AI 失敗或沒設金鑰時自動改用規則。
- **房間**：每個連結帶 `?room=xxxx`。同一個房間的人看到同一份資料（每 2 秒同步）；按「分享」複製連結，就能一台當業務、一台當生管。
- **工廠時間**：示範從 14:20 開始，按「+10 分」「+30 分」「到收工」讓時間前進；勾「自動」時，沒人按也會照規則備料、推料。

## 部署到 Vercel（約 10 分鐘）

1. **上傳程式碼**：把這個資料夾推到自己的 GitHub repository。
2. **建立專案**：到 vercel.com → Add New → Project → 選這個 repository → 直接按 Deploy（Vercel 會自動辨認 Vite）。
3. **加資料庫**：專案頁 → Storage → Create Database → 選 **Upstash（Redis）** → 免費方案 → 連到這個專案。環境變數會自動加好。
4. **加 AI 金鑰**：專案頁 → Settings → Environment Variables，二選一：
   - `ANTHROPIC_API_KEY` = 你的 Claude API 金鑰（可另設 `ANTHROPIC_MODEL`，預設 `claude-haiku-5-5`）
   - `OPENAI_API_KEY` = 你的 OpenAI 金鑰（可另設 `OPENAI_MODEL`，預設 `gpt-4o-mini`）
5. **重新部署**：Deployments → 最新一筆 → Redeploy。
6. 打開網址，右上角應該顯示「共用資料」和「AI 已連線」兩個綠點。

沒做第 3 步：資料只存在各自的瀏覽器（顯示「本機資料」）。
沒做第 4 步：智能體改用規則（顯示「AI 未設定・用規則」）。兩種情況都還能完整操作。

## 本機開發

```bash
npm install
npm run dev
```

`npm run dev` 只跑前端，會用本機資料與規則。要連同 `/api` 一起測，可用 `npx vercel dev`（需登入 Vercel）。

## 檔案

```
api/world.js        房間資料（Upstash Redis，版本號防止同時寫入互相覆蓋）
api/ai.js           智能體（Anthropic 或 OpenAI；每個 IP 每分鐘限 30 次）
src/engine/         排程規則、試算、時間推進、指標與異常
src/store.ts        同步：讀寫房間資料，失敗時改用本機
src/ai.ts           呼叫智能體，失敗時改用規則
src/views/          六個角色畫面
```

## 排程規則

1. 各線有優先客戶：1 線甲、2 線甲→乙、3 線乙、4 線丙→乙
2. 下一張鎖住，只准同機種插單
3. 1 線空檔先補甲明天的單
4. 甲的追加：算好料到的時間才停線
5. 被停的單回自己客戶的線，接在正在做的後面
